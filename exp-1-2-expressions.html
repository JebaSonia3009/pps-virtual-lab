Expression Evaluation and Operator Precedence

Unit 1 · Decision Making · Estimated time: 45 minutes

Aim

To understand the order in which C evaluates the operators in an arithmetic expression, and how the types of the operands decide the type and value of the result.

Learning outcomes

After completing this experiment, a student will be able to:

  1. State the relative precedence of the arithmetic operators and the effect of parentheses.
  2. Apply associativity to decide the order of two operators of equal precedence.
  3. Predict the result of integer division and of the modulus operator, including with negative operands.
  4. Explain implicit type promotion and identify where an expression changes from integer to floating-point arithmetic.
  5. Reduce a compound expression to its final value one operator at a time, in the correct order.

Prerequisites

Experiment 1.1 — data types, memory and assignment.

Theory

An expression such as a + b * c contains more than one operator, so the compiler must decide which to apply first. That decision is not made left to right. It is governed by two fixed rules — precedence and associativity — and can be overridden only by parentheses.

Precedence

Every operator has a precedence level. An operator of higher precedence binds its operands more tightly and is therefore applied first.

LevelOperatorsAssociativity
Highest( )Left to right
Unary - (negation)Right to left
*   /   %Left to right
Lowest+   -Left to right

So in a + b * c, the multiplication is performed first and its result becomes the right operand of the addition. Parentheses raise a subexpression to the top of the order: (a + b) * c forces the addition first.

Associativity

Precedence does not settle everything. In 100 / 5 * 2, both operators sit at the same level. Associativity decides: the arithmetic operators associate left to right, so the division happens first, giving 20 * 2 and a result of 40. Reading it as 100 / (5 * 2) would give 10, which is a common and costly mistake.

Integer division

The / operator does not have one meaning. When both operands are integers, C performs integer division and discards the fractional part: 7 / 2 is 3, not 3.5. The result is truncated towards zero, so -7 / 2 is -3. If either operand is a floating-point value, the same symbol performs real division instead.

This is why float avg = total / n; so often produces a wrong average. If total and n are both int, the division is done in integer arithmetic and the fraction is lost before the result is stored in the float.

The modulus operator

% yields the remainder after integer division and requires both operands to be integers; applying it to a float is a compile-time error. In C the result takes the sign of the left operand, so -7 % 2 is -1 while 7 % -2 is 1. The identity (a / b) * b + a % b == a holds in every case.

Implicit type promotion

When an operator receives one integer and one floating-point operand, the integer is converted to floating-point first and the operation is carried out in floating-point. The conversion applies to a single operation, not to the whole expression, so an expression can begin in integer arithmetic and switch part of the way through.

Compare these two:

5 / 2 * 2.0   →  2 * 2.0    →  4.0     /* division done first, in integers */
2.0 * 5 / 2   →  10.0 / 2   →  5.0     /* promotion happens before the division */

The same three numbers and the same three operators give different answers, purely because of where the promotion occurred.

How the reduction proceeds

Evaluating an expression is a sequence of reductions. At each step the compiler finds the operator that must be applied next, replaces it and its two operands with a single value, and repeats until one value remains. The Demo shows exactly this, one reduction at a time.
