Introduction

Beginning programmers can usually write a C program that compiles, yet still be unable to say why it produced the output it did. The gap is that a compiler hides everything interesting: how a value is stored in memory, why 5/2 is 2 and not 2.5, how the call stack grows and shrinks during recursion, where the null terminator sits at the end of a string, and what actually happens on the heap when malloc is called.

This virtual lab makes those hidden steps visible. Each experiment pairs a short body of theory with an interactive simulation that executes a C construct one step at a time, showing the state of memory and the reason for every decision as it happens. Students then work through a practice section where they predict the behaviour themselves and receive a hint, rather than the answer, when they are wrong.

The lab complements the physical programming laboratory rather than replacing it. Students still write and compile their own code; the virtual lab explains what the machine did with it. It runs entirely in a web browser, needs no installation and no login, and works on a phone as well as on a desktop computer.

Objectives

The key objectives of this virtual lab are:

  1. To give students a concrete mental model of memory in C — how values of each data type are stored, how arrays occupy contiguous locations, how the stack holds function calls, and how the heap is managed by hand.
  2. To make the order of evaluation visible, so that operator precedence, associativity, type promotion and short-circuit logic become predictable rather than memorised.
  3. To let students observe control flow directly: the path taken through a decision, the iterations of a loop, and the expansion and contraction of the call stack during recursion.
  4. To support reasoning about cost, by counting iterations, recursive calls and memory used, so that students can compare an iterative and a recursive solution on evidence.
  5. To develop the habit of predicting a program's output before running it, which is the foundation of debugging.
  6. To provide self-assessment through graded pretests and posttests attached to every experiment.

List of Experiments

Experiments are released as they are completed. Each contains Aim, Theory, Procedure, Pretest, Demo, Practice, Posttest, References, Contributors and Feedback.

UNIT 1

Decision Making

12 hours
1.1

Memory, Data Types and Assignment

Size, range and storage of int, float and char. Format specifiers, overflow, and tracing program state through assignment statements including variable swapping.

Building first
1.2

Expression Evaluation and Operator Precedence

Step-by-step collapse of an arithmetic expression. Precedence, associativity, integer division and type promotion.

Planned
1.3

Decision Making: if…else and switch

Flowchart tracing for if, if…else and else-if ladders. Boolean expressions and range checks. Case selection, fall-through when break is missing, and a comparison of switch with the else-if ladder.

Planned
UNIT 2

Modularity

12 hours
2.1

Functions, the Call Stack and Pointers

Stack frames created and destroyed as functions are called and return. Pass by value compared with pass by reference, with pointer variables shown as arrows into memory.

Planned
2.2

Recursion and the Call Stack

The stack expanding to the base case and contracting as values return. Recursion tree and stack shown side by side for factorial, digit counting, GCD and palindrome checking.

Planned
UNIT 3

Array and String

12 hours
3.1

Array Memory Layout and Indexing

Contiguous storage, address arithmetic, why indices start at zero, and what happens when an index goes out of bounds.

Planned
3.2

Strings and String Functions

The null terminator and its consequences. Character-by-character execution of strlen, strcpy, strcat, strcmp, strchr and strstr, with the buffer shown throughout.

Planned
3.3

Loop Tracing: while, do…while and for

Iteration tables showing the condition test, body and update in order. Why do…while always executes once. Linear search animated for successful and unsuccessful cases.

Planned
UNIT 4

Structured Iterations

12 hours
4.1

Nested Loops and Pattern Generation

The i–j iteration table alongside the output being printed cell by cell. Iteration counts for patterns such as the hollow square.

Planned
4.2

Two-Dimensional Arrays and Matrix Traversal

Row-major storage in memory. Row sums, column sums, diagonals, and testing a matrix for sparseness.

Planned
4.3

Searching and Sorting: Recursion against Iteration

Bubble sort traced pass by pass with comparison and swap counts. Binary search implemented both ways, reporting recursive calls made against loop iterations, together with the stack cost of each.

UNIT 5

Memory Driven Problems

12 hours
5.1

Structures and Arrays of Structures

Field layout in a memory block. Structures passed by value compared with by reference, showing when a copy is made and when the original is modified.

Planned
5.2

Dynamic Memory Allocation

A live view of the heap through malloc, calloc, realloc and free. Uninitialised memory compared with zeroed memory, the cost of resizing, and what a memory leak or a dangling pointer looks like.

Planned
5.3

File Handling

The file position indicator moving through a text file as fscanf and fgets read from it, and why testing feof after a read behaves differently from testing it before.

Target Audience

  • First-year undergraduate students of engineering taking an introductory programming course in C, across all branches.
  • Diploma and polytechnic students studying computer programming fundamentals.
  • Students in higher semesters revising C before a data structures course or a placement examination.
  • Teachers who wish to demonstrate memory layout, expression evaluation, recursion and dynamic allocation during a classroom lecture.

No prior programming experience is assumed. A student needs only a web browser and an internet connection.
