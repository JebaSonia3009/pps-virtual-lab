Pointers and Helper Functions

Unit 2 · Modularity · 19 programs to explore · Estimated time: 70 minutes

Aim

To use pointer variables to reach and change memory directly, and to break a larger problem into small helper functions that each return an answer.

Learning outcomes

After completing this experiment, a student will be able to:

  1. Declare a pointer, store an address in it with &, and reach the value it points to with *.
  2. Say clearly what p holds and what *p is, and never confuse the two.
  3. Change a variable through a pointer, aim a pointer somewhere else, and have two pointers reach the same variable.
  4. Write helper functions that return an int, a float or a char, and call one helper from inside another.
  5. Write the same helper two ways — returning an answer, and writing the answer through a pointer — and say when each is the better choice.
  6. Build a modular program from several helpers, such as a student scorecard or a set of temperature converters.

Prerequisites

Experiment 2.1 — functions, the call stack, pass by value and pass by reference.

How to use this experiment

Watch three things together at every step: the memory panel for the boxes and arrows, the reader underneath it that spells out p against *p, and the observation at the bottom. The Playground lets you try the same ideas yourself with nothing running.

Theory

Everything in this experiment comes from one simple fact: every variable lives at an address, and C lets you hold that address in another variable and use it to reach the original. Nothing more mysterious than that.

A house and its address

Think of a variable as a house with something inside it, and the address as the postal address written on an envelope. The address is not the house, and it is certainly not what is inside the house — but with the address in your hand you can get to the house whenever you like, and change what is inside.

The two operators

int  a = 5;        /* an ordinary variable            */
int *p = &a;       /* p holds the ADDRESS of a        */

printf("%d", a);    /* 5  — the value, read directly   */
printf("%d", *p);   /* 5  — the same value, through p  */

*p = 9;             /* changes a itself to 9           */

& means "the address of". *, used on an existing pointer, means "the value at that address".

The thing everyone mixes up

If you remember one line from this experiment, remember this one:

p is an address. *p is a value.

Writing p = 9; does not put 9 into a — it tries to make p point at memory location 9, which is nonsense and usually crashes the program. Writing *p = 9; is what puts 9 into a. The reader panel under the memory in this experiment shows both at every step, so you can keep checking yourself.

The star means two different things

Where it appearsWhat it means
int *p; — in a declaration"p is a pointer to an int"
*p = 9; — in a statement"the variable p points to"

They look identical and mean different things. This is simply something to get used to.

Aiming a pointer somewhere else

A pointer is an ordinary variable, so it can be given a new value whenever you like. p = &b; makes the arrow swing across to b. Nothing happens to a or to b — only the pointer changed.

Two pointers, one variable

Nothing stops two pointers holding the same address. Then *p and *q reach the very same box, and a change made through one is immediately visible through the other. One variable, two ways of getting to it.

Helper functions that return a value

A helper function is a small function that does one job and hands back the answer. The type at the front says what kind of answer it gives:

int   add(int x, int y)   { return x + y; }       /* gives back a whole number */
float average(int t, int n){ return (float) t / n; }/* gives back a decimal     */
char  findGrade(int m)    { ... return 'B'; }      /* gives back a letter       */
int   isEven(int n)       { return n % 2 == 0; }   /* gives back 1 or 0         */

The last one is worth looking at twice. A condition in C is just the number 1 or 0, so a helper that answers a yes-or-no question simply returns that number — and the caller can use it straight away as a condition: if (isEven(n)) { … }.

Return a value, or write through a pointer?

The same job can usually be done either way. Compare these two, which both decide whether a number is prime:

int isPrime(int n)                  void checkPrime(int n, int *result)
{                                   {
    ...                                 ...
    return 1;                           *result = 1;
}                                   }

answer = isPrime(7);                checkPrime(7, &answer);

They do exactly the same work. The difference is only in how the answer travels back: one returns it, the other writes it into a variable whose address it was given.

Use a return value when…Use a pointer when…
there is one answer there are two or more answers
the caller just wants the result the function must change the caller's own variable
you want the simpler, safer code the answer is too big to copy (arrays, later on)

For a first-year program, prefer returning a value. It is easier to read and it cannot damage anything by accident. Reach for a pointer when one return value is genuinely not enough.

Breaking a program into helpers

A scorecard program has three separate jobs inside it: add the marks, work out the average, decide the grade. Give each one its own function and main becomes a short, readable plan:

int   total = calculateTotal(m1, m2, m3);
float avg   = calculateAverage(total, 3);
char  grade = findGrade(avg);

Each helper is short enough to check on its own, and each can be reused by any other program that needs the same job done.

One small thing about division

In calculateAverage you will see (float) total / n. Both total and n are whole numbers, so without that cast C would do integer division and throw the fraction away. Writing (float) in front converts total to a decimal first, so the division keeps its fraction.
