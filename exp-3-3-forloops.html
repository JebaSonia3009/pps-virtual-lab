Count-Controlled for Loops and Linear Search

Unit 3 · Array and String · 35 programs to explore · Estimated time: 80 minutes

Aim

To use a for loop where the number of passes is known in advance, control the direction and size of its step, and apply it to the standard numeric problems: generating sequences, computing aggregates, printing patterns, searching an array, and tracking values across passes.

Learning outcomes

After completing this experiment, a student will be able to:

  1. Write a count-controlled for loop and say exactly how many passes it will make before running it.
  2. Step a loop up or down, and by any amount, and work out the number of passes from the start, the stop and the step.
  3. Generate a sequence, compute an aggregate (sum, count, average, maximum) and print a pattern using nested loops.
  4. Track a value across passes with a running variable — a total, a counter, or the best value seen so far — and explain why it is set up before the loop.
  5. Implement linear search and handle both the successful and the unsuccessful case correctly.
  6. Use break to stop a loop early and continue to skip one pass, and say what each one does to the step and the test.
  7. Write functions that take arrays: printing an array in reverse, countFrequency, and mergeStrings using for loops only.

Theory

Count-controlled means you know the number in advance

A loop is count-controlled when you can say how many passes it will make before you run it. "Print the first 10 even numbers" and "add up these 6 marks" are count-controlled. "Keep asking until the user types 0" is not — nobody knows how many passes that will take. The for loop is built for the first kind, which is why its start, test and step sit together on one line where you can read all three at once.

for (i = 1; i <= 10; i = i + 1)
/*   start    test       step   */

How many passes will it make?

For a loop that steps upwards, the count is:

passes = (stop - start) / step + 1       /* when the test uses <= */
LoopValues takenPasses
for (i = 1; i <= 5; i = i + 1)1 2 3 4 55
for (i = 0; i < 5; i = i + 1)0 1 2 3 45
for (i = 1; i < 5; i = i + 1)1 2 3 44
for (i = 0; i <= 10; i = i + 2)0 2 4 6 8 106
for (i = 5; i >= 1; i = i - 1)5 4 3 2 15
for (i = 10; i >= 0; i = i - 2)10 8 6 4 2 06

Rows three and one differ by a single character and by one pass. For walking an array of n elements the correct form is for (i = 0; i < n; i = i + 1) — start at 0, stop before n, because the last index is n - 1. Writing i <= n there reads one element past the end of the array.

Stepping down, and stepping by more than one

Three things have to agree, or the loop runs zero times or for ever:

DirectionTestStep
Counting upi <= stop or i < stopi = i + k
Counting downi >= stop or i > stopi = i - k

Mixing them is a classic fault: for (i = 5; i <= 1; i = i - 1) never runs, because the test is false immediately; for (i = 1; i <= 5; i = i - 1) never stops, because the step moves away from the test. Both are in the Demo.

Tracking a value across passes

Most loop problems need one variable that survives from pass to pass and is finished only when the loop ends. It is always set up before the loop, never inside it — inside, it would be reset on every pass and never accumulate anything.

JobStart it atInside the loop
Running total0total = total + a[i];
Running product1p = p * a[i];
Counter0count = count + 1;
Largest so fara[0]if (a[i] > big) big = a[i];

Note the last row. Starting big at 0 is a real bug: if every value is negative, the answer comes back as 0, which is not in the array at all. Start it at the first element instead. The Demo shows both versions on negative data.

Linear search

Linear search looks at each element in turn until it finds what it wants or runs out of elements. Both endings have to be handled, and the second is the one students forget:

int search(int a[], int n, int key) {
    int i = 0;
    for (i = 0; i < n; i = i + 1) {
        if (a[i] == key) {
            return i;          /* successful: give back WHERE it was found */
        }
    }
    return -1;                 /* unsuccessful: -1 means "not here" */
}

Why -1? Because every valid index is 0 or more, so -1 cannot be mistaken for a position. Returning 0 for "not found" would be a bug, since 0 is a perfectly good index — the first one.

CaseWhat happensPasses
Found at the frontReturns on the first pass1
Found in the middleReturns part way throughindex + 1
Found at the endReturns on the last passn
Not foundEvery element is checked, then -1n

The unsuccessful case is the slowest: it is the only one that must examine every element before it can be sure. That is the honest cost of searching an unsorted array.

break and continue

A search can be written either with return inside the loop, as above, or with a found variable and a break. Both are in the Demo. The return version is shorter; the break version is what you need when there is still work to do after the loop.

Nested loops and patterns

A pattern needs two loops: the outer one counts the rows, the inner one counts what goes on a row. The inner loop runs completely, from start to finish, for every single pass of the outer one.

for (i = 1; i <= 4; i = i + 1) {        *
    for (j = 1; j <= i; j = j + 1) {    **
        printf("*");                    ***
    }                                   ****
    printf("\n");
}

The shape comes from the inner loop's test. Here it is j <= i, so row i gets i stars, which gives a growing triangle. Change the inner test and the shape changes. The total number of inner passes is 1 + 2 + 3 + 4 = 10 — the Demo counts them for you.

Procedure

  1. Read the Theory, especially the table of how many passes each loop makes.
  2. Attempt the Pretest before looking anything up.
  3. Open the Demo at Counting with for. For each program, work out the number of passes before you run it, then check it against the iteration table.
  4. In Stepping up and down, change the step and watch how many passes it produces. Then run the two broken loops — the one that never runs and the one that never stops — and work out why from the table.
  5. In Sequences and aggregates, note where each running variable is set up, and try the "largest" program with all-negative values to see the bug that a starting value of 0 causes.
  6. In Linear search, search for a key that is present and then one that is absent, and compare the number of passes. Try the first element and the last.
  7. In Patterns, count the inner passes for a triangle of 4 rows before running it.
  8. In The three practice functions, work through reverse printing, countFrequency and mergeStrings.
  9. Use the Explorer to build a for header yourself and see how many passes it makes before you commit to it.
  10. Work through the Practice section in both modes.
  11. Attempt the Posttest and compare it with your pretest score.
