Decision Making: if…else and switch

Unit 1 · Decision Making · Estimated time: 60 minutes

Aim

To understand how a C program chooses between alternative courses of action, using if, if…else, the else-if ladder and switch, and how a Boolean condition is evaluated to decide which path is taken.

Learning outcomes

After completing this experiment, a student will be able to:

  1. Evaluate a condition built from relational and logical operators and state whether it is true or false.
  2. Explain that C has no separate Boolean type: a condition yields the integer 1 or 0, and any non-zero value counts as true.
  3. Trace an else-if ladder and state exactly which conditions are tested and which are skipped.
  4. Describe short-circuit evaluation of && and || and identify when the right-hand operand is never evaluated.
  5. Form correct range checks and classification conditions for problems such as leap year, vowel or consonant, and eligibility tests.
  6. Trace a switch statement, explain the role of break, and predict the effect of omitting it.
  7. Choose appropriately between a switch and an else-if ladder.

Prerequisites

Experiments 1.1 and 1.2 — data types, memory, assignment and expression evaluation.

Theory

Every program so far has run straight from the first statement to the last. A decision statement breaks that: it tests a condition and executes one block of statements rather than another. The statements that are skipped are not executed at all — the program jumps over them.

There is no Boolean type in C

In C a condition is an ordinary integer expression. A relational operator such as < produces the value 1 when the relation holds and 0 when it does not. So 7 > 3 is literally the number 1.

Conversely, when a value is used as a condition, C asks only one question: is it zero? Zero means false; every other value, positive or negative, means true. This is why if (n) is a valid way to write if (n != 0), and why the classic slip if (n = 0) compiles happily. That statement assigns 0 to n and then tests the result, which is 0, so the body never runs.

Arithmetic binds more tightly than relational, which binds more tightly than &&, which binds more tightly than ||. So a + 1 > b && c == d means ((a + 1) > b) && (c == d). Parentheses are still worth writing for the reader.

Short-circuit evaluation

&& and || do not always evaluate both sides. For A && B, if A is false the whole expression must be false, so B is never evaluated. For A || B, if A is true the result is already known and B is skipped.

This is a guarantee of the language, not an optimisation, which is why if (n != 0 && total / n > 5) is safe: when n is zero the division is never performed.

The else-if ladder

An else-if ladder tests its conditions in order and stops at the first one that is true. Every later condition is skipped without being evaluated. Order therefore matters: writing if (m >= 40) … else if (m >= 75) … means the second test can never be reached, because anything at least 75 is also at least 40.

The ladder is also why a range check needs only one bound after the first test. Once m >= 75 has been ruled out, a later m >= 60 already implies m < 75.

The switch statement

A switch compares one integer expression against a list of constant labels and jumps directly to the matching one. The controlling expression must be of an integer type — int or char, but not float and not a string — and each case label must be a compile-time constant. A range such as case x > 10: is not permitted.

Why break matters

A case label is a point of entry, not a block. Once control has jumped to a label, execution continues straight through the following cases until it meets a break or reaches the end of the switch. Omitting break therefore makes a menu selection perform every operation below it as well. Deliberate fall-through is occasionally useful — several labels sharing one body — but an accidental one is a classic bug.

A menu of four operations is clearer as a switch. A grade band such as marks >= 75 cannot be written as a switch at all.

Procedure

Step 1

Read the Theory and attempt the Pretest. Note your score.

Step 2

Open the Demo and select Odd or even. Change the input value, press Reset, then Step through. Watch the condition panel substitute the value, reduce the arithmetic, and settle on true or false before any branch is entered.

Step 3

Select Positive, negative or zero. Enter a positive number and note in the Decision path panel that the later conditions are never tested. Then enter a negative number and observe how many conditions are evaluated before one succeeds.

Step 4

Select Leap year and try 2024, 1900 and 2000 in turn. For 1900, note precisely which part of the condition fails. For 2000, note that the year is a leap year for the reason given by the second half of the condition, not the first.

Step 5

Select Vowel or consonant and enter a vowel near the start of the alphabet, such as a. Observe in the condition panel that the remaining comparisons are struck through: they were never evaluated, because || short-circuits.

Step 6

Run Bank menu using switch and then The same menu with break removed with the same choice. Compare the two outputs carefully.

Step 7

Open Practice. For each program and input, write down the expected output before entering it. Complete at least eight correctly.

Step 8

Attempt the Posttest.
