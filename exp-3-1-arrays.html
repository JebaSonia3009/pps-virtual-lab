Arrays and Strings

Unit 3 · Array and String · 33 programs to explore · Estimated time: 80 minutes

Aim

To store a collection of values in a single named block of memory, reach any one of them by its index, and understand that a string in C is nothing more than an array of characters with a hidden marker at the end.

Learning outcomes

After completing this experiment, a student will be able to:

  1. Declare and initialise a one-dimensional array and a string in C.
  2. Reach any element with a[i] and any character with s[i], and say why the first index is 0 and the last is size - 1.
  3. Explain contiguous storage — that the boxes sit next to each other at consecutive addresses — and work out the address of any element.
  4. Describe the '\0' terminator and what goes wrong without it.
  5. Use strlen, strcpy, strcat, strcmp, strrev, strchr and strstr, and read what each one returns.
  6. Explain why an array name used on its own is the address of its first element, and why a function that takes an array can change the caller's data.
  7. Write recursive functions over arrays and strings: the length of a string, the largest element, a vowel count, and printing a string backwards.
  8. Recognise an out-of-range index as a real bug that C does not catch for you.

Theory

Why arrays exist

Suppose you need the marks of 60 students. You could write int m1, m2, m3, … sixty times, but then a loop cannot help you: there is no way to say "the next one". An array gives the whole collection one name and numbers the members, so a loop can walk through them.

int marks[60];          /* 60 boxes, all called marks, numbered 0 to 59 */
marks[0] = 78;          /* the first  */
marks[59] = 55;         /* the last   */

Declaring and initialising

Written asWhat you get
int a[5];5 boxes, nothing put in them yet
int a[5] = {10, 20, 30, 40, 50};5 boxes, all filled
int a[5] = {10, 20};5 boxes; the other three are set to 0
int a[] = {7, 8, 9};3 boxes — C counts them for you

Indexes start at 0

An array of 5 has indexes 0, 1, 2, 3, 4. There is no a[5]. This is not a quirk: the index is the distance from the start, and the first element is zero boxes away from the start.

Writing a[5] on an array of 5 is the most common array bug there is. C does not check it. A real compiler will build the program, run it, and quietly read or write memory belonging to something else — often with no error message at all, and sometimes with a wrong answer that appears only on another machine. In this lab the program stops and tells you the valid range, so you can see the mistake instead of chasing it.

Contiguous storage: the whole reason arrays are fast

The boxes of an array are not scattered. They sit touching each other in memory, in order. If a[0] is at address 0x7FE0 and each int takes 4 bytes, then:

ElementAddressWorked out as
a[0]0x7FE0start + 0 × 4
a[1]0x7FE4start + 1 × 4
a[2]0x7FE8start + 2 × 4
a[i]—start + i × 4

So the computer never searches for a[i]. It does one multiplication and one addition, and it is there. That is why reading a[59] costs exactly as much as reading a[0]. The Demo prints the real address under every box, so this is visible rather than merely claimed.

A string is an array of characters

C has no separate string type. A string is a char array that ends with a special character, '\0', called the null terminator. Its value is the number zero, and it marks where the text stops.

char s[] = "cat";

index    0     1     2     3
       +-----+-----+-----+-----+
       | 'c' | 'a' | 't' | \0  |      4 boxes for 3 letters
       +-----+-----+-----+-----+

This single fact explains a great deal:

  • strlen("cat") is 3, but the array needs 4 boxes. The terminator is stored but not counted.
  • char s[3] = "cat"; does not fit — there is no room for the terminator.
  • Every string function works by walking forward until it meets '\0'. Without it, they keep walking into memory that is not theirs.

The string library

These live in <string.h>, so a program that uses them needs #include <string.h> at the top.

FunctionWhat it doesWhat it gives back
strlen(s)Counts characters up to, but not including, '\0'the count
strcpy(dest, src)Copies src into dest, terminator includeddest
strcat(dest, src)Adds src onto the end of destdest
strcmp(a, b)Compares in dictionary order0 if equal, negative if a comes first, positive if b does
strrev(s)Turns s around in places
strchr(s, c)Finds the first cthe address of it, or NULL
strstr(a, b)Finds b inside athe address of the match, or NULL

Two traps worth saying out loud. First, strcmp returns 0 when the strings are the same — so if (strcmp(a, b)) is true when they differ, which reads backwards and catches everybody once. Second, strchr and strstr hand back an address, not a position, which is why printing the result with %s shows the rest of the string from that point onwards.

strrev is not part of standard C. It exists in Turbo C and in Microsoft's compiler, and your syllabus lists it, so it is included here — but on gcc it will not compile, and a reversing loop or a recursive function has to be written by hand. The Demo shows both.

Arrays and pointers are closely related

An array name used on its own means the address of its first element. These two lines do exactly the same thing:

int *p = a;
int *p = &a[0];

And once a pointer is aimed into an array, four spellings all reach the same box:

Written asMeans
a[2]the element 2 boxes along from the start of a
*(a + 2)the same thing, written with pointer arithmetic
p[2]2 boxes along from wherever p points
*(p + 2)the same thing again

Note what p + 1 means: not "one byte further", but one whole element further. For an int * that is 4 bytes; for a char * it is 1. The pointer knows the size of what it points at.

Why a function can change your array

In Experiment 2.1 we saw that a function gets a copy of each value passed to it. An array is the exception, and the reason is the rule above: when you write total(marks, 5), what is passed is the address of marks[0], not 60 copied boxes. So:

  • Passing a large array costs nothing — one address travels, however big the array.
  • The function can change the caller's data, because it is reaching the original boxes through that address.
  • int a[] and int *a in a parameter list mean exactly the same thing. The Demo shows the parameter as int * with an arrow pointing back at the caller's first box, which is the truth of what happened.
  • Inside the function the array's length is unknown, which is why the count is almost always passed as a second parameter.

Recursion over an array or a string

A string has a natural base case built in: s[i] == '\0' means "there is nothing left". An array has no such marker, so the index or the count has to be carried along as a parameter — which is exactly what "use a helper function to manage the index" means.

int myLength(char s[], int i) {
    if (s[i] == '\0') return 0;          /* base case: the end marker */
    return 1 + myLength(s, i + 1);       /* one more, plus the rest   */
}

Compare it with strlen on the same text in the Demo: the answers agree, and the trace panel shows the stack growing one level per character and then unwinding.

Procedure

  1. Read the Theory, especially the box diagram of char s[] = "cat".
  2. Attempt the Pretest before looking anything up.
  3. Open the Demo at the first tab, Arrays. Step through the first program and watch the boxes appear side by side. Read the addresses under them and check that each one is 4 more than the box before it.
  4. Run Asking for an index that does not exist and read what the lab says.
  5. Move to Strings. Find the \0 box, shaded, at the end of the text, and see how the boxes after it are leftovers rather than part of the string.
  6. In The string library, run strcmp on equal strings and note that the answer is 0, then run strcat and watch where the new characters are written.
  7. In Arrays and pointers, compare a[2], *(a + 2), p[2] and *(p + 2) and confirm the arrow lands on the same box each time.
  8. In Recursion on arrays and strings, work through the recursive length, the largest element, the vowel count and the backwards printing.
  9. Use the Explorer to build an array or a string by hand and watch each box change as you write to it.
  10. Work through the Practice section in both modes.
  11. Attempt the Posttest and compare it with your pretest score.
