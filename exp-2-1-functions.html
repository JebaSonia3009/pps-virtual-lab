Functions, Pass by Value and Pass by Reference

Unit 2 · Modularity · 20 programs to explore · Estimated time: 70 minutes

Aim

To understand how a problem is broken into smaller functions, what happens in memory when a function is called and when it returns, and how passing a value differs from passing an address.

Learning outcomes

After completing this experiment, a student will be able to:

  1. Break a larger problem into smaller functions, each doing one job.
  2. Describe the stack frame created for a call and say what it holds.
  3. Explain that a parameter is a copy, so changing it cannot affect the caller's variable.
  4. Use & to take the address of a variable and * to reach the variable a pointer points to.
  5. Write a function that changes a caller's variable by receiving its address.
  6. Choose correctly between returning a value and using a pointer parameter.

Prerequisites

Unit 1 — data types and memory, expressions, and decision making.

How to use this experiment

The Demo has four concepts. Watch the Call stack panel at every step: a new box appears when a function is called and disappears when it returns.

Theory

So far every program has been one long main. That works for ten lines. It stops working for a hundred. A function is a named piece of a program that does one job, and splitting work into functions is the first real engineering skill in programming.

Breaking a problem into sub-tasks

Take the task "print a student's scorecard: total, average and grade". That is really three smaller jobs:

  • add the marks together,
  • divide to get the average,
  • turn the average into a letter grade.

Each one becomes a function. Each is short enough to check on its own, each can be reused, and main becomes a readable summary of the whole plan rather than a wall of arithmetic.

A good rule for first-year programs: if you can describe a piece of the work in one short sentence, it should probably be a function.

Writing a function

int square(int x) {        /* int = what it gives back            */
    return x * x;          /* x   = what it needs to be given      */
}

The type at the front is what the function hands back. void means it hands back nothing — it just does something, such as printing. The things in the brackets are the parameters: the information the function needs in order to work.

The call stack

When a function is called, the computer sets aside a block of memory for it called a stack frame. The frame holds that call's parameters and its local variables. Frames pile up: the function that is running sits on top, and the one that called it waits underneath.

When the function returns, its frame is thrown away. Every parameter and every local variable inside it stops existing at that moment. Only the returned value survives.

Parameters are copies — pass by value

C passes arguments by value. When you call square(n), the current value inside n is copied into the parameter x. They are two separate variables at two different addresses that happen to start out holding the same number.

So changing a parameter changes only the copy. This is exactly why the obvious swap function does nothing:

void swap(int x, int y) {   /* x and y are copies          */
    int t = x;
    x = y;
    y = t;                  /* the copies are exchanged    */
}                           /* the frame is thrown away    */

The exchange really happens — but to the copies, which vanish when the function returns. The caller's variables were never touched.

Addresses and pointers

Every variable lives at an address in memory. The operator & gives you that address: &a means "the address of a".

A pointer is a variable whose value is an address. It is declared with a * in its type:

int  a = 5;
int *p = &a;      /* p holds the address of a */

The * means two different things depending on where it appears, and this trips everyone up at first:

WhereWhat it means
int *p; — in a declarationp is a pointer to an int
*p — in an ordinary statementthe variable p points to

So *p reads the value in a, and *p = 9; stores 9 into a itself. Using * this way is called dereferencing.

Pass by reference

C has no true pass by reference, but passing an address gives the same effect. The address is still copied into the parameter — so the pointer itself is passed by value — but a copy of an address still leads back to the original variable, and writing through it reaches the real thing:

void swap(int *x, int *y) {   /* x and y hold addresses     */
    int t = *x;
    *x = *y;
    *y = t;                   /* writes into the caller     */
}

swap(&a, &b);                /* pass addresses, not values */

Which should you use?

SituationUse
The function works out one answerReturn it: return x * x;
The function must change the caller's variablePass its address
The function must produce two or more answersPass addresses for the extras
The function only reads the valuePass by value — it is simpler and safer

Prefer returning a value when you can. A function that only reads what it is given is easier to understand and cannot damage anything by accident.

One trap worth knowing

Calling addHundred(n); and then wondering why n did not change is common. If the function returns the new value, you must store it: n = addHundred(n);. A returned value that nobody catches is simply thrown away.
