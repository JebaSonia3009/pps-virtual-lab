Functions, the Call Stack and Pointers

Unit 2 · Modularity · Estimated time: 60 minutes

Aim

To understand what happens in memory when a function is called and when it returns, and to distinguish passing an argument by value from passing it by reference using a pointer.

Learning outcomes

After completing this experiment, a student will be able to:

  1. Describe the stack frame created for a function call and state what it contains.
  2. Explain that a parameter passed by value is a copy, and that changing it cannot affect the caller's variable.
  3. Read and write the operators & (address of) and * (dereference), and state the type of a pointer variable.
  4. Implement a function that modifies a caller's variable by receiving its address.
  5. Explain why a local variable ceases to exist when its function returns.
  6. Decompose a problem into helper functions and trace the calls made.

Prerequisites

Experiments 1.1 to 1.3 — memory, data types, assignment, expressions and decisions.

Theory

A function is a named block of code with its own private workspace. Splitting a program into functions is not only about tidiness: it changes where variables live and who can see them.

The call stack

When a function is called, the machine reserves a region of memory for it called a stack frame (or activation record). The frame holds the function's parameters, its local variables, and a record of where to return to. Frames are stacked: the most recent call sits on top, and only the topmost function is currently running.

When the function returns, its frame is removed and the memory is released. Everything inside it — every parameter, every local variable — ceases to exist. This is why a local variable cannot be read after its function has finished, and why returning the address of a local variable is a serious error.

Parameters are copies

C passes arguments by value. When square(n) is called, the current value of n is copied into the parameter inside the new frame. The parameter is a separate variable at a different address that merely happens to start with the same value.

Assigning to a parameter therefore changes only the copy. This is exactly why the familiar swap function does not work:

void swap(int x, int y) {    /* x and y are copies      */
    int t = x;
    x = y;
    y = t;                   /* the copies are exchanged */
}                            /* the frame is destroyed   */

The exchange genuinely happens — but to the copies, which are discarded when the function returns. The caller's variables were never touched.

Addresses and pointers

Every variable has an address. The operator & produces it: &a is the address of a. A pointer is a variable whose value is an address. It is declared with a * in the type:

int  a = 5;
int *p = &a;    /* p holds the address of a  */

The * operator used on an existing pointer means something different from the * in a declaration. In an expression, *p means "the variable that p points to". Reading *p fetches a's value; assigning *p = 9 stores 9 into a itself. This is called dereferencing.

The type matters. int * is a pointer to an int; the compiler needs to know the pointed-to type in order to read the right number of bytes.

Passing by reference

C has no true pass-by-reference, but the same effect is achieved by passing an address. The address is itself copied into the parameter — so the pointer is passed by value — but the copy still refers to the caller's variable, and writing through it reaches the original:

void swap(int *x, int *y) {  /* x and y hold addresses    */
    int t = *x;
    *x = *y;
    *y = t;                  /* writes into the caller     */
}

swap(&a, &b);               /* pass addresses, not values */

Return values

A function that computes a single result should normally return it rather than write through a pointer. Use a pointer parameter when the function must modify a caller's variable, or when it must produce more than one result.

Decomposition

A problem such as producing a student's scorecard breaks into independent parts: compute the total, compute the average, decide the grade. Each becomes a small function that is easy to test on its own and can be reused. The stack panel in the Demo shows each helper being called and returning in turn.

Procedure

Step 1

Read the Theory and attempt the Pretest. Note your score.

Step 2

Open the Demo and select Calling a function. Step through and watch the stack panel: a second frame appears when the call is made, and disappears when the function returns. Note the addresses — the parameter has a different address from the caller's variable.

Step 3

Select Pass by value — the swap that fails. Watch the exchange succeed inside the function and then vanish with the frame. Say in your own words why the caller's variables are unchanged.

Step 4

Select Pass by reference — the swap that works. Compare the two programs side by side. Note in the stack panel that the parameters now hold addresses, and that the caption under each pointer names the variable it refers to.

Step 5

Run Student scorecard. Observe that only one helper frame exists at a time: each is created and destroyed before the next call begins.

Step 6
