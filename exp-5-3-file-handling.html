File Handling

Unit 5 · Memory Driven Problems · 36 programs to explore · Estimated time: 90 minutes

Aim

To keep data after a program has finished, by reading it from and writing it to text files with the standard C functions — fopen, fscanf, fgets, fgetc, feof and fclose — and to use what is read to count, total, average and report.

Learning outcomes

After completing this experiment, a student will be able to:

  1. Explain why data in variables disappears when a program ends, and what a file is for.
  2. Open a file with fopen, choose the right mode, and check the result against NULL before using it.
  3. Close a file with fclose and say what is lost if it is not closed.
  4. Read numbers with fscanf, and use its return value — the number of items it filled in — to control a reading loop.
  5. Read a whole line with fgets, explain why the newline comes with it, and remove it.
  6. Read a single character with fgetc and recognise EOF.
  7. Say exactly what feof reports, and why while (!feof(fp)) processes the last item twice.
  8. Count lines, words and characters in a text file.
  9. Store what is read in variables or an array, and compute counts, totals and averages from it.
  10. Produce a frequency report from a file of numbers.
  11. Write results to a file with fprintf, and distinguish "w" from "a".

Theory

Why files exist

Everything in the previous experiments lived in memory: variables in frames, blocks on the heap. All of it disappears the moment the program ends. Even memory asked for with malloc and never freed is taken back by the operating system when the program stops.

A file is data that outlives the program that wrote it. The marks a program calculates today can be read by a different program tomorrow. In the memory picture on this page, files are drawn in a dashed block of their own, below the stack and the heap, because that is what they are: a third place, and the only one that survives.

Opening a file

FILE *fp = fopen("marks.txt", "r");

FILE * is a pointer to information the library keeps about an open file — where it is, and how far through it you have read. You never look inside it; you only pass it to the other functions. It needs no header beyond #include <stdio.h>, which you have had all along.

The second argument is the mode:

modewhat it doesif the file is not there
"r"read from the beginning returns NULL — it will not create one
"w"write, emptying the file first creates it
"a"append — add to the end, keeping what is there creates it

Be careful with "w". Opening an existing file for writing throws away everything in it before a single character is written. If you meant to add to it, the mode is "a".

Always check what fopen gives back

if (fp == NULL) {
    printf("cannot open the file");
    return 1;
}

A file may be missing, misspelled, or in a different folder. If fopen fails it returns NULL, and every later call with that pointer is a mistake. Two of the programs in the Demo show what happens without the check.

And every file that is opened should be closed with fclose(fp). Closing makes sure anything written is really on the disk and releases the handle; a program that writes and then forgets to close can lose the lot.

Reading numbers: fscanf and its return value

while (fscanf(fp, "%d", &n) == 1) {
    count = count + 1;
    total = total + n;
}

fscanf works exactly like scanf, but reads from a file instead of the keyboard. The & is needed for the same reason: it passes the address, so fscanf can change your variable.

The important part is what it returns: the number of items it successfully filled in. Ask for one and get 1, and the read worked. Get 0, and there was something there that was not a number. Get EOF, and the file is finished. Testing that number is the reliable way to drive a reading loop — which brings us to the one mistake almost everybody makes first.

Why while (!feof(fp)) is wrong

feof does not mean "the position is at the end". It means "a read has already tried to go past the end and failed". That one step of delay is the whole problem:

while (!feof(fp)) {          /* wrong */
    fscanf(fp, "%d", &n);
    printf("%d ", n);
}

After the last number is read, the position is at the end but nothing has yet failed, so feof is still false. The loop goes round once more, fscanf fails, n is left holding the previous value — and it is printed a second time. A file of five numbers reports six. The Demo has this program beside the correct one so you can compare the output directly.

The cure is to let the read decide: while (fscanf(...) == 1), or while (fgets(...) != NULL), or while ((c = fgetc(fp)) != EOF). In each case the loop continues only when something was actually read.

Reading lines: fgets

char line[80];
while (fgets(line, 80, fp) != NULL) {
    lines = lines + 1;
}

fgets takes three things: where to put the text, how much room there is, and the file. The middle one is what makes it safe — it will never write more than that many characters, so it cannot run off the end of your array. It returns the array, or NULL when there is nothing left.

Two details that catch people out. First, fgets keeps the newline: a line of 11 characters comes back as 12. Removing it is a common three lines:

len = strlen(line);
if (len > 0 && line[len - 1] == '\n') {
    line[len - 1] = '\0';
}

Second, the last line of a file may have no newline at all, in which case it comes back without one. Both cases appear in the Explorer.

Reading characters: fgetc

c = fgetc(fp);
while (c != EOF) {
    chars = chars + 1;
    c = fgetc(fp);
}

One character at a time, and EOF when there are none left. Note that c is declared int, not char — EOF is a negative value that no real character has, and a char may not be able to hold it.

Counting lines, words and characters

This is your guided practice, and it is the classic exercise for a reason: the counting rule for words has to be stated exactly. A word is a run of characters with a separator on each side, where a separator is a space, a tab or a newline. The program keeps a flag saying whether it is currently inside a word, and adds one every time it goes from outside to inside.

Forget that a newline is a separator and the first word of every line after the first goes uncounted. The Demo has that exact mistake as a program of its own, next to the correct version — it reports 6 words where the file holds 8.

A frequency report

Your practice exercise is a file of many numbers and a report of how often each appears. The method is the one from Unit 3: an array used as a set of counters, one per possible value.

int count[11];
for (i = 0; i <= 10; i = i + 1) {
    count[i] = 0;                    /* clear them first */
}
while (fscanf(fp, "%d", &n) == 1) {
    if (n >= 0 && n <= 10) {
        count[n] = count[n] + 1;     /* the value IS the index */
    }
}

Two things matter here. The counters must be cleared before use, exactly as in Experiment 5.2 — an array declared this way holds whatever was in that memory. And every value read must be checked against the range before it is used as an index: one stray number in the file and count[n] writes outside the array, which C will not stop. The Demo has a file with values outside the range so you can watch them being counted separately and left out.

Writing: fprintf

fprintf(fp, "%d appears %d time(s)\n", i, count[i]);

fprintf is printf with a file in front. Everything about the format string is the same; the only difference is where the text goes. A report written this way does not appear on the screen at all — look at the file panel in the Demo to see it arrive.

The same file, read two ways

One last idea, and it is worth more than any function on this page. A text file is only characters. Nothing in it says whether it holds numbers, words or lines. What it means is decided entirely by the function you choose to read it with: fgets sees lines, fscanf("%d") sees numbers, fgetc sees one character at a time — and all three are looking at exactly the same bytes. The Explorer lets you put any text in a file and read it both ways at once.

Procedure

  1. Answer the Pretest before reading the Theory.
  2. Read the Theory as far as Always check what fopen gives back.
  3. Open the Demo at Opening and closing. Run the first program and look at the file panel: the file is shown with a marker for the read position, which has not moved yet.
  4. Run Reading three numbers, one after another and step through it slowly, watching the marker move along the file after each fscanf.
  5. Run A file that is not there, then Forgetting to check whether it opened. The second one stops; read why.
  6. Move to Reading numbers. Run Count, total and average. Now edit the file in the box above the program — add a number, remove one — and watch every figure change.
  7. Run Why while (!feof(fp)) reads the last value twice and then The same loop written properly. Compare the two outputs carefully and write down the difference.
  8. Open Reading lines. Run fgets keeps the newline and note the length it reports, then Taking the newline off again.
  9. Run Counting lines, words and characters — your guided practice — then A word counter that misses words, and find the one condition that differs between them.
  10. Open Making a report. Run How often each value appears, which is your practice exercise, then the version drawn as bars. Edit the file and watch the report follow.
  11. Run Values outside the range the report expects and note why the range check is there.
  12. Open Writing to a file. Run Writing a few lines and look at out.txt in the file panel filling up. Then run Opening with w empties what was there and Opening with a adds to the end instead one after the other.
  13. Use the Explorer: paste in some text of your own and read it both as text and as numbers. Put a word in the middle of the number file and see where the reading stops.
  14. Do the Practice questions in both modes until your streak reaches five.
  15. Answer the Posttest.

Guided practice

Read a text file line by line and count the number of characters, words and lines in it.

It is the fourth program in the Reading lines tab. Write your own first, then compare — and check your word-counting rule against the file that has three lines, because that is where most versions go wrong.

Practice

  1. Read a file containing many numbers and produce a frequency count report: how many times each value appears.

The Making a report tab has it three ways — as a list, as bars, and written out to a second file. Say in your record what your program does with a value that falls outside the range of your counters, and why that matters.

An honest note on what this page models. The files here live in the page, not on a
      disk: each program carries its own file contents, which you can edit, and nothing is saved when you
      close the browser. Everything about how the functions behave — what each one returns,
      when the read position moves, when feof becomes true, what "w" does to an
      existing file — follows the clauses above. What is not modelled is the part that varies between
      systems anyway: buffering, file permissions, and what happens when two programs open the same file
      at once. Text written on one line here may also appear with a different line ending on Windows,
      where a newline is stored as two characters rather than one; the counts your own compiler reports
      can differ from this page for that reason alone.
