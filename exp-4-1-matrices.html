Nested Loops, Matrices and Bubble Sort

Unit 4 · Structured Iterations · 32 programs to explore · Estimated time: 85 minutes

Aim

To trace a nested loop and predict both its output and its number of iterations, to use nested loops to print patterns and to walk a two-dimensional array, and to implement bubble sort and follow it pass by pass.

Learning outcomes

After completing this experiment, a student will be able to:

  1. Trace a nested loop and predict its printed output.
  2. Count the total number of inner iterations, and say how that count grows as n grows.
  3. Declare and initialise a two-dimensional array, and explain row-major storage — that a matrix is one straight block of memory, not a grid.
  4. Work out the address of m[i][j], and say which index chooses the row and which chooses the column.
  5. Walk a matrix row-wise and column-wise, and compute row sums, column sums and both diagonals.
  6. Print patterns, including a hollow square, by choosing the right inner test and the right condition for what to print.
  7. Implement bubble sort, trace its comparisons and swaps, and explain why the inner loop gets shorter with every pass.
  8. Apply a threshold to decide whether a matrix is sparse.

Theory

Reading a nested loop

The rule is short: the inner loop runs completely, from its start to its finish, for every single pass of the outer loop. Everything else follows from that.

for (i = 1; i <= 3; i = i + 1) {        i = 1:  j = 1, 2
    for (j = 1; j <= 2; j = j + 1) {    i = 2:  j = 1, 2
        printf("%d%d ", i, j);          i = 3:  j = 1, 2
    }
}                                       prints  11 12 21 22 31 32

Note that j goes back to 1 at the start of every outer pass, because the for loop's start clause runs each time the inner loop begins. Forgetting to reset a counter that is declared outside is a common fault, and it is in the Demo.

Counting the iterations

ShapeInner iterationsAt n = 10
Both loops go to n (a square)n × n100
Inner goes to i (a triangle)n(n + 1) / 255
Inner goes to n - i (bubble sort)n(n − 1) / 245

All three grow like n squared. Double n and the work roughly quadruples: a square loop at n = 10 does 100 iterations, at n = 20 it does 400, and at n = 100 it does 10,000. This is what is meant by the "time taken" to solve a problem — not seconds on a clock, which depend on the machine, but how many steps the program takes, which does not. The Demo counts the iterations for you so you can watch the number grow.

A triangle does a little over half the work of a square, and bubble sort a little under half — but all three are n squared. Halving the work does not change how it grows; it only shifts the line.

A two-dimensional array is one straight block

We draw a matrix as a grid because that is how we think about it, but memory has no grid. The rows are laid down one after another, in order:

int m[3][4];        /* 3 rows of 4 = 12 boxes, all in a row */

   row 0        row 1        row 2
+--+--+--+--+ +--+--+--+--+ +--+--+--+--+
|00|01|02|03| |10|11|12|13| |20|21|22|23|
+--+--+--+--+ +--+--+--+--+ +--+--+--+--+
 ^                ^
 m[0][0]          m[1][0]  -- the box right after m[0][3]

This is called row-major order, and it gives the address formula:

address of m[i][j] = start + (i × columns + j) × size of one element

For int m[3][4] starting at 0x7FD0, m[1][2] is at 0x7FD0 + (1 × 4 + 2) × 4 = 0x7FD0 + 24. Note that the number of columns appears in the formula and the number of rows does not — which is why, when a matrix is passed to a function, C must be told the column count but can manage without the row count.

The Demo draws the matrix as a grid, but the figures under the heading tell you the truth: how many boxes, where the block starts, and that it is stored row-major. Hover any cell to see its real address.

Which index is which

WrittenMeansIf it is wrong
m[i][j], first indexthe row Too large → outside the matrix altogether
m[i][j], second indexthe column Too large → runs into the next row

That second case is worth dwelling on. In int m[3][4], asking for m[0][4] does not fall off the end of the world: it lands exactly on m[1][0], because the rows touch. A real C compiler will not say a word, and the program will read a real value — just the wrong one. This lab stops and tells you, which is the only way to see the mistake while you are learning it.

Walking a matrix: row-wise and column-wise

for (i = 0; i < rows; i = i + 1)        for (j = 0; j < cols; j = j + 1)
    for (j = 0; j < cols; j = j + 1)        for (i = 0; i < rows; i = i + 1)
        /* m[i][j] -- row by row */             /* m[i][j] -- column by column */

The two differ only in which loop is outside. Row by row follows the order the boxes sit in memory; column by column jumps a whole row's width at every step. Both give the same total, and both are in the Demo.

WantedHow
Sum of row iReset the total, then add m[i][j] for every j
Sum of column jReset the total, then add m[i][j] for every i
Main diagonalAdd m[i][i] — the cells where row equals column
Other diagonalAdd m[i][n - 1 - i]

Both diagonals need only one loop, not two, because fixing i fixes j as well.

Sparse matrices

A matrix is called sparse when most of its entries are zero. "Most" needs a number, so a threshold is chosen — commonly that more than two thirds of the entries are zero. Counting the zeros takes one nested loop; the decision is then a single comparison.

if (zeros * 3 > rows * cols * 2)      /* more than two thirds are zero */

Written that way the test uses only whole numbers, so there is no rounding to worry about. Writing zeros / (rows * cols) > 0.66 instead would make zeros / (rows * cols) an integer division, which is 0 for every matrix that is not entirely zero — a bug that looks like it works. The Demo shows both.

Bubble sort

Bubble sort compares each neighbouring pair and swaps them if they are in the wrong order. One pass of that does not sort the array, but it does guarantee one thing: the largest value left has been carried to the end, like a bubble rising. Repeat, and the array sorts itself from the back.

for (i = 0; i < n - 1; i = i + 1) {           /* n-1 passes       */
    for (j = 0; j < n - 1 - i; j = j + 1) {   /* shrinking by one */
        if (a[j] > a[j + 1]) {
            temp = a[j];                      /* the three-line   */
            a[j] = a[j + 1];                  /* swap -- a temp   */
            a[j + 1] = temp;                  /* is essential     */
        }
    }
}

Two details carry the whole idea:

  • Why n - 1 - i? After pass 1 the last element is already in its final place, after pass 2 the last two are, and so on. Comparing them again would be wasted work, so the inner loop gets shorter each time. That is where n(n − 1) / 2 comes from.
  • Why the temp? Writing a[j] = a[j+1]; first destroys the old a[j], and the second line then copies the value back onto itself. Both values end up the same. The Demo runs that broken version so you can watch it happen.

In the Demo the two cells being compared are highlighted on every comparison, so you can follow the pair moving along the array and see the sorted tail growing from the right.

Procedure

  1. Read the Theory, especially the diagram of how int m[3][4] actually sits in memory.
  2. Attempt the Pretest before looking anything up.
  3. Open the Demo at Nested loops. For each program, predict the output and the number of inner iterations before running it, then check both against the iteration tables.
  4. Run Forgetting to reset the inner counter and work out from the tables why the output is short.
  5. In Patterns, build up to the hollow square. Work out the condition that decides whether a position gets a star or a space before you read it.
  6. In Matrices, step through the declaration and watch the addresses. Hover a cell to see which address it is. Then run Reading past the end of a row.
  7. In Rows, columns and diagonals, work through the three sums the syllabus asks for, and check that the row totals and the column totals add up to the same grand total.
  8. In Bubble sort, step through slowly and watch the highlighted pair move along, then the sorted tail grow. Count the comparisons and check them against n(n−1)/2. Then run the version with the broken swap.
  9. Use the Explorer to build a matrix by hand, fill it, and read off row, column and diagonal sums as you go.
  10. Work through the Practice section in both modes.
  11. Attempt the Posttest and compare it with your pretest score.
