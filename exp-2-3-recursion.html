Recursion and the Call Stack

Unit 2 · Modularity · 20 programs to explore · Estimated time: 75 minutes

Aim

To solve a problem by letting a function call itself on a smaller version of the same problem, and to watch the call stack grow to the base case and shrink again as answers are handed back.

Learning outcomes

After completing this experiment, a student will be able to:

  1. Recognise a problem whose answer depends on the answer to a smaller version of itself.
  2. Write the two parts every recursive function needs: the base case that answers without calling again, and the recursive case that calls itself on something smaller.
  3. State the recurrence relation for factorial, digit counting, GCD, power and Fibonacci.
  4. Trace the call stack as it expands to the base case and contracts as values return, and say what each waiting call is waiting for.
  5. Explain why a missing base case makes the program stop, and what the stack looks like when it happens.
  6. Handle corner cases such as 0 and single-digit numbers correctly.
  7. Compare a recursive solution with a loop and say which is clearer and which does less work.

Theory

The idea in one sentence

A recursive function solves a big problem by asking itself to solve a slightly smaller problem, and then doing one small piece of work with the answer it gets back.

Think of counting the people in a queue when you cannot see the whole queue. You ask the person in front of you, "how many people are ahead of you?" They ask the person in front of them. The question travels forward until it reaches the first person, who can answer without asking anyone: "nobody is ahead of me." That answer then travels back down the queue, each person adding one to it, until it reaches you.

Two things make this work, and recursion needs exactly the same two things:

The partWhat it doesIn the queue
Base case Answers immediately, without calling again. Stops the recursion. The first person says "nobody."
Recursive case Calls itself on something smaller, then does one small piece of work with the answer. Everyone else asks forward, then adds one.

If the base case is missing, the question travels forward forever and never comes back. If the recursive call is not on something smaller, it never reaches the base case. Both mistakes end the same way: the program stops.

The shape of every recursive function

int solve(int n) {
    if (/* the smallest case */) {
        return /* the answer, with no further call */;   /* base case */
    }
    return /* one small step */ solve(/* something smaller */);   /* recursive case */
}

Factorial, written out

The mathematical definition is already recursive:

Recurrence relationIn C
0! = 1if (n == 0) return 1;
n! = n × (n−1)!return n * fact(n - 1);

Reading fact(5) out loud: 5 factorial is 5 times 4 factorial. And 4 factorial is 4 times 3 factorial. And so on, down to 0 factorial, which is simply 1. Nothing is multiplied until the bottom is reached — the multiplications all happen on the way back up:

fact(5) = 5 × fact(4)                    going down: nobody can answer yet
  fact(4) = 4 × fact(3)
    fact(3) = 3 × fact(2)
      fact(2) = 2 × fact(1)
        fact(1) = 1 × fact(0)
          fact(0) = 1                    base case reached, the first real answer
        fact(1) = 1 × 1   = 1          coming back up: now the work happens
      fact(2) = 2 × 1   = 2
    fact(3) = 3 × 2   = 6
  fact(4) = 4 × 6   = 24
fact(5) = 5 × 24  = 120

Two phases, and why they matter

Every recursion has a going-down phase (calls being made, frames piling up, nothing answered yet) and a coming-back phase (answers returning, frames being thrown away, the work being done). Where you put your printf decides which phase you see:

CodePrintsWhy
printf before the recursive call5 4 3 2 1 Work happens on the way down.
printf after the recursive call1 2 3 4 5 Work waits until the answers come back.

These two programs differ by one moved line, and they print in opposite orders. Both are in the Demo, side by side. If a student understands that pair, they understand recursion.

Why the stack is the whole story

Each call gets its own stack frame with its own copy of n. When fact(5) calls fact(4), the frame for fact(5) does not go away — it waits, holding its own n of 5, because it still has a multiplication to do once the answer arrives. That is why seven frames exist at the deepest moment of fact(5): main, plus one each for 5, 4, 3, 2, 1 and 0. The Demo's counter says the same thing — deepest 7 frames.

The Demo shows these frames stacked, the newest on top, and a trace beside them telling you which calls are still waiting and which have given their answer back.

One recursion that is different

Look closely at GCD. On the way back up it does no work at all — it just passes the answer along unchanged. Factorial multiplies on the way back; GCD does not. Recursions that do nothing on the way back are called tail recursive, and they are the ones that can be rewritten as a loop most easily. Students do not need the word, but they should notice the difference, and the trace panel makes it visible.

Fibonacci, and the cost of repeating work

fib(n) = fib(n-1) + fib(n-2) is correct and beautiful, and also wasteful. Each call splits into two, so the same small problems get solved again and again — fib(5) alone makes 15 calls, and fib(9) makes 109. The Demo counts the calls for you, so a student can watch the number grow and see for themselves why a loop is faster here, even though the recursion is easier to read.

Recursion against iteration

RecursionLoop
Reads likeThe definition of the problemA set of instructions
MemoryOne stack frame per levelOne frame, whatever the size
RiskStack runs out if it goes too deepLoops forever if the test never fails
Best forProblems defined on smaller versions of themselvesPlain repetition

Neither is "better". Use whichever matches the shape of the problem.

Procedure

  1. Read the Theory, especially the written-out trace of fact(5).
  2. Attempt the Pretest. Do not look anything up first — the point is to find out what you already think.
  3. Open the Demo and start with the first concept tab, How recursion works. Step through Counting down and then Counting up. They are the same program with one line moved. Watch the output appear in a different order and look at the trace panel to see why.
  4. Step through Factorial slowly. At each step read the trace panel on the right: which calls are still waiting, and which have given an answer back.
  5. Run A base case that never happens and read what the lab tells you when the stack runs out.
  6. Move to Counting digits. Trace it to the base case, then try n = 0 and n = 7 and explain the answers.
  7. In Classic recursions, run Fibonacci and watch the call counter. Compare it with the loop version.
  8. Open the Explorer and drive the recursion yourself — go down one level at a time until you reach the base case, then hand the answers back up one at a time.
  9. Work through the Practice section until you get several right in a row in both modes.
  10. Attempt the Posttest and compare your score with the pretest.
