break, continue and the Cost of Repetition

Unit 4 · Structured Iterations · 30 programs to explore · Estimated time: 80 minutes

Aim

To understand exactly what break and continue do inside a loop, to measure the difference between them — one ends the loop, the other ends only one pass — and to compare the memory and the work of an iterative and a recursive solution to the same problem.

Learning outcomes

After completing this experiment, a student will be able to:

  1. State what break does in a for, while and do…while loop, and where the program carries on afterwards.
  2. State what continue does, and explain why the step of a for loop still runs when it does.
  3. Show by measurement that continue does not reduce the number of passes a loop makes, while break does.
  4. Recognise the mistake that makes continue hang a while loop, and write the loop so that it cannot happen.
  5. Explain that break and continue affect only the innermost loop containing them.
  6. Write a loop that reads values with scanf until a stopping value arrives, and say what happens if that value never comes.
  7. Take a number apart digit by digit using % 10 and / 10.
  8. Write the sum of a number's digits both iteratively and recursively, count the intermediate steps of each, and account for the difference.
  9. Compare the memory behaviour of the two versions: a loop holding one frame against a recursion holding one frame per digit.

Theory

Two ways to leave early

An ordinary loop ends in one way: its test becomes false. C gives a loop two more exits, and the whole of this experiment is about telling them apart.

  • break ends the loop. The rest of the pass is abandoned, the test is never checked again, and the program carries on at the first statement after the loop.
  • continue ends this pass. The rest of the body is abandoned, but the loop itself is very much alive: it goes straight on to its next pass.

Students mix these up constantly, and the reason is that in a short program they often print the same thing. The difference only shows itself when you count the passes, which is what the Demo and the Explorer on this page do for you.

What break costs, and what it saves

Searching a list of eight values for one that sits at index 3: with break the loop looks at four boxes and stops. Without it, the loop looks at all eight and finds the same answer. Four passes were saved — real work that never happened.

What break does not save is memory. The loop's variables were created once when the function started and they are still there afterwards. Leaving a loop early makes a program finish sooner; it does not make it smaller.

What continue does not do

This is the single most useful thing on this page, and it surprises almost everyone.

Take a loop counting from 1 to 20 that uses continue to skip the multiples of 4. It prints 15 numbers instead of 20. It is tempting to conclude that the loop therefore did less work. It did not. The loop still made all 20 passes: it still tested i <= 20 twenty times, still ran i = i + 1 twenty times, and still entered the body twenty times. All continue did was walk out of the body early on five of those passes.

continue changes what the body does. break changes how many times the body runs. The Explorer measures both so you can see it rather than take it on trust.

continue and the step of a for loop

A for loop keeps its step in the head of the loop, so continue cannot skip it: control jumps to the step, the step runs, the test runs, and the next pass begins. That is why the loop above still counted all the way to 20.

A while loop has no such protection, and this is where the classic bug lives:

int i = 1;
while (i <= 6) {
    if (i == 3) {
        continue;           /* i = i + 1 below is skipped */
    }
    printf("%d ", i);
    i = i + 1;
}

When i reaches 3 the continue jumps straight back to the test. But i = i + 1 sat below the continue, so it never runs again. i stays 3, the test stays true, and the program hangs. One of the programs in the Demo is exactly this loop, and the page stops it and explains what happened.

The cure is to advance the counter before the continue can be reached, or to use a for loop, where the language does it for you.

They reach only one loop

In two nested loops, a break in the inner loop leaves the inner loop only. The outer loop carries on with its next pass as though nothing had happened. The same is true of continue. There is no form of break in C that leaves two loops at once.

Reading until a stopping value

Often a program does not know in advance how many values it will be given. The usual arrangement is a stopping value (also called a sentinel): an agreed value that cannot be real data, which means "that is all". Here a negative number stops the reading.

int n = 0, count = 0, total = 0;
while (1) {
    scanf("%d", &n);
    if (n < 0) {
        break;
    }
    count = count + 1;
    total = total + n;
}

while (1) means "go on forever", because 1 is never false. The loop is not actually endless: the break is the way out, and writing it this way puts the stopping rule in plain sight in the middle of the body, where the value has just been read.

The & in scanf("%d", &n) is not decoration. It passes the address of n, which is the only way scanf can reach inside your function and change the variable. This is the pass-by-reference idea from Unit 2, met again in the standard library.

If the stopping value never arrives, the loop asks for another number and there is none. In the Demo you can try exactly that: the page stops the program and says so.

One honest caveat. scanf returns the number of values it managed to read, and careful programs test it — if (scanf("%d", &n) != 1) { ... } — so that letters typed where a number was expected, or input that has simply run out, are noticed instead of ignored. The programs on this page leave that test out so that the shape of the loop stays in view, which is the usual convention in a first course. It is worth knowing that production code does not.

Taking a number apart

Two operators do the whole job on a non-negative integer:

  • n % 10 gives the last digit.
  • n / 10 — integer division — gives everything else, the last digit discarded.

Starting from 4071: 4071 % 10 is 1 and 4071 / 10 is 407; then 7 and 40; then 0 and 4; then 4 and 0. Once n reaches 0 there is nothing left, and that is the loop's stopping condition. The same two operators reverse a number, count its digits, and test whether it is a palindrome.

Sum of digits, counted both ways

The loop keeps a running total and peels one digit per pass:

int sumIter(int n) {
    int s = 0;
    while (n > 0) {
        s = s + n % 10;
        n = n / 10;
    }
    return s;
}

The recursion says the same thing in one line: the last digit, plus the sum of the digits of what is left.

int sumRec(int n) {
    if (n == 0) {
        return 0;
    }
    return n % 10 + sumRec(n / 10);
}

For 4071 the loop runs 4 passes, one per digit. The recursion makes 5 calls: one for each digit and one more with n == 0, which is the base case that stops it. That extra step is not waste — it is how the recursion knows to stop, exactly as the loop's test n > 0 is how the loop knows. The two are doing the same arithmetic in the same order.

What each one costs in memory

Here the two part company. The loop uses one stack frame, whatever the number is. The recursion opens a new frame for every digit, and every one of them stays open until the deepest call returns, because each is waiting to add its own digit to what comes back.

For a four-digit number that is five frames against one — nothing at all. For a number with a million digits it would be a million frames, and the program would run out of stack long before it finished. This is why depth matters more than call count when judging a recursion: a recursion whose depth stays small, like one digit at a time, is perfectly safe, and the cost panel beside the Demo lets you watch it either way.

Counting with a global

To count the steps of both versions, the programs on this page use a variable declared outside every function:

int steps = 0;        /* a global: no frame owns it */

A global is created before main begins and lives until the program ends, so every function can read and change it. In the memory picture it is drawn in a dashed block of its own, apart from the stack. Globals are the right tool for a counter in a teaching program like this one, but professional code uses them sparingly: because any function can change one, a wrong value gives no clue about which function did it.

Procedure

  1. Answer the Pretest first, before reading the Theory. It checks what you already know about loops, about % and /, and about recursion.
  2. Read the Theory, paying particular attention to What continue does not do.
  3. Open the Demo at the tab break: leaving early. Run the first program and watch the value of i when the loop stops. Change stop to 21 and run it again: the break now never happens.
  4. Run the two searching programs one after the other and compare the number of boxes looked at. Both find the same answer.
  5. Move to continue: skipping one pass. Run the first program, then the second, which prints the same numbers without using continue at all. Note in your record that continue is a matter of style here, not of power.
  6. Run How many were printed, how many were skipped and read the last number it prints carefully. The loop ran 20 passes even though it printed 15 numbers.
  7. Run The classic continue mistake. The page will stop it. Read the explanation, then run The same loop written safely and find the one line that moved.
  8. Open Reading until a stop value. The box marked typed input holds the numbers the person at the keyboard types. Change them and run again. Then delete the negative number from the box and run it once more to see what happens when the stopping value never arrives.
  9. Open Sum of digits, two ways. Run the loop version and the recursive version on the same number and check that the answers agree. Then run Both ways, with the steps counted and record the two step counts.
  10. Use the Explorer. Build a loop, press Build and measure, and read the table: the row for continue and the row for the plain loop run the same number of passes. Record this; it is the central result of the experiment.
  11. Do the Practice questions in both modes until your streak reaches five.
  12. Answer the Posttest.

Guided practice

Write a program that prints all the numbers from 1 to 20 except the multiples of 4, using a for loop and continue to skip them. It is the first program in the continue tab; write it yourself first, then compare.

Practice

  1. Write a program that reads numbers continuously until the user enters a negative number, using a while loop, and show how break leaves the loop the moment the stopping condition is met.
  2. Write two functions that compute the sum of the digits of a number — one using iteration and one using recursion — and compare the number of intermediate steps each one takes.

Both are in the Demo, with the step counts printed by the programs themselves. Write your own version first; use the Demo to check it and to see what it costs.
