Structures and Arrays of Structures

Unit 5 · Memory Driven Problems · 37 programs to explore · Estimated time: 90 minutes

Aim

To group data of different types under a single name using a struct, to build and work with arrays of structures that hold many records, and to see exactly what happens when a record is passed to a function — copied when passed by value, reached in place when passed by reference.

Learning outcomes

After completing this experiment, a student will be able to:

  1. Declare a struct that groups members of different types, and explain why an array could not hold the same group.
  2. Reach a member with the dot operator, and change one member without disturbing the others.
  3. Describe the memory of a structure: one block, the members laid side by side, each at a known distance from the start.
  4. Build an array of structures and say where record i begins, given the base address and the size of one record.
  5. Walk an array of records with a loop to total, count, compare and find.
  6. Pass a structure to a function by value and show that the function works on a copy, so the caller's record is unchanged.
  7. Pass a structure by reference with a pointer, use -> to reach its members, and show that the caller's record does change.
  8. Write a function that takes a structure and returns an updated structure, and explain why the caller must assign the result back.
  9. Write a function that searches an array of structures for a record and returns it, and explain why returning the position is sometimes more useful than returning the record.
  10. Explain why an array passed to a function is never copied, while a single structure is.

Theory

The problem a structure solves

An array holds many things of one type. But an employee is an id, a name and a salary — an int, some text and a float. No array can hold that group, and keeping three separate variables works only until there are two employees, when you need id1, name1, salary1, id2, name2, salary2 and the program starts to come apart.

A struct is C's answer: it makes one new type out of several existing ones.

struct Employee {
    int id;
    char name[20];
    float salary;
};

That declares no variable and uses no memory. It describes a shape. Variables of that shape come afterwards:

struct Employee e = {101, "Asha", 25000};

Note the semicolon after the closing brace of the declaration. Leaving it out is the single most common mistake with structures, and the error the compiler gives is unhelpful.

Reaching the members

The dot operator names one member of one record: e.id, e.name, e.salary. Each behaves exactly like a variable of its own type, so e.salary = 30000; changes that member and touches nothing else.

One member is different. e.name is a char array, and C never lets you assign to a whole array, so e.name = "Lakshmi"; is not allowed. Use strcpy(e.name, "Lakshmi"); instead, exactly as in Unit 3.

What a record looks like in memory

One structure is one block, with the members laid out in the order they were declared, each immediately after the one before:

struct Employee  (28 bytes)
 +-------------+--------------------------+-------------+
 | id  4 bytes | name  20 bytes           | salary 4    |
 +-------------+--------------------------+-------------+
 byte 0        byte 4                      byte 24

Because each member sits at a known distance from the start, e.salary costs nothing to find: the compiler already knows it is 24 bytes along.

Here is the part worth noticing. Those 28 bytes are exactly what the same three facts would cost as three loose variables. A structure adds no memory at all. What it adds is a single name for the group — and that name is what lets the whole record be copied, passed to a function and returned in one piece.

An honest detail: a compiler is allowed to insert unused padding bytes so that each member starts at an address its type prefers, which can make sizeof bigger than the sum of the members. The structures in this experiment are arranged so that no padding is needed, which is why the arithmetic in the Explorer comes out exactly. In real code, reordering the members can change the size of a structure without changing a single member.

Many records: an array of structures

Once there is a shape, an array of that shape holds many records:

struct Employee list[3] = {{101, "Asha",  25000},
                           {102, "Ravi",  31000},
                           {103, "Meera", 28000}};

The records sit one after another, 28 bytes each, 84 bytes in all. So record i begins at base + i × 28, and list[i].salary is one multiplication and one addition away. Reaching record 7 costs no more than reaching record 0 — the computer never looks through the records in between.

From there everything is a loop over records: total the salaries, count how many are above a figure, find the largest, search for an id. The loop is the same shape as every loop from Unit 3; only a[i] has become list[i].member.

Passing a record to a function, by value

A structure given to a function in the ordinary way is copied, member by member, into the function's own frame:

void tryRaise(struct Employee e) {
    e.salary = 99999;          /* changes this frame's copy only */
}

After tryRaise(a); the salary in main is unchanged. Students find this surprising because it does not happen with arrays; watch it in the Demo, where two separate records appear in two separate frames.

So how does a function change a record? Two ways, and the syllabus asks for both.

Returning an updated structure

The first way is to hand the record back:

struct Employee giveRaise(struct Employee e, int amount) {
    e.salary = e.salary + amount;
    return e;
}

A whole structure can be returned, and the copy is made before the frame is thrown away, so this is perfectly safe — unlike returning the address of a local variable, which would point at a frame that no longer exists. The caller must do something with what comes back:

a = giveRaise(a, 5000);        /* keeps the result   */
giveRaise(a, 5000);            /* works it out and throws it away */

This style has a quiet advantage: the function cannot damage anything the caller did not ask it to change.

Passing a record by reference

The second way is to pass the address, so the function reaches the caller's own record:

void raise(struct Employee *e) {
    e->salary = e->salary + 5000;
}
...
raise(&a);

The arrow -> means "follow this address, then take that member". It is shorthand for (*e).salary, which is what it does underneath, and it exists because that form is awkward to read and easy to get wrong.

The dot and the arrow are not interchangeable. e.salary is for a record; p->salary is for a pointer to one. Using a dot on a pointer is a compile error, and one of the programs in the Demo shows exactly what the page says when you try.

Passing by reference also avoids copying. For a 28-byte record that hardly matters; for a large record copied inside a loop it matters a great deal, which is why professional code often passes a pointer even when it has no intention of changing anything.

Arrays are different

An array of structures passed to a function is never copied. What arrives is the address of the first record, exactly as in Unit 2, which is why a function written as

void raiseAll(struct Employee list[], int n, int amount)

can change every record in the caller's array without a pointer appearing anywhere in main. One structure is copied; an array of them is not. That asymmetry catches people out, and it is worth saying aloud: struct Employee list[] as a parameter really means struct Employee *list.

Searching an array of records

Searching for a record is the linear search of Unit 3 with one change — the test looks at a member:

if (list[i].id == wanted) { ... }

What to hand back is the interesting question, and there are two answers.

  • Return the record. Natural to read and safe, because the caller gets a copy and cannot damage the list by accident. But it is a copy: changing it does not change the list. You also need some way to signal "not found" — usually a record with an impossible id, such as 0.
  • Return the position. Less tidy, but -1 is an unmistakable "not found", and because the caller has the index it can go on to change the record with list[at].salary = 40000;.

Both are in the Demo, including the program that shows a returned record being changed while the list stays exactly as it was. If a search is meant to lead to an update, return the position or a pointer; if it is meant only to report, return the record.

Procedure

  1. Answer the Pretest before reading the Theory.
  2. Read the Theory as far as What a record looks like in memory.
  3. Open the Demo at One record, many types. Step through the first program and watch the record appear as a single block with its members inside it. Note the size and the address of each member.
  4. Run the second program, Three loose variables, and compare the bytes it uses with the bytes the structure used. They are the same. Write that down; it is the answer to "does a structure cost extra memory?".
  5. Run Changing one member leaves the rest alone and watch which box lights up.
  6. Run Text members are changed with strcpy, then try changing the name with = in your own compiler and read the error the compiler gives.
  7. Move to Arrays of records. Step through the first program and watch the three records appear one after another. Check that each record starts 28 bytes after the one before it.
  8. Run Asking for a record that is not there and read what the page says.
  9. Open Passing a record by value. Step slowly through The function gets a copy and watch two separate records exist in two separate frames at the same time. This is the step most worth watching in the whole experiment.
  10. Run Taking a record and returning an updated one, then The caller keeps the result by assigning it back, and note the one line that differs.
  11. Open Passing a record by reference. Run The same job, both ways, side by side and satisfy yourself that both arrive at the same answer by different routes. Then run A dot on a pointer does not work.
  12. Open Searching the records. Run the search that returns the record and the one that returns the position, then The copy a search returns is not the record itself.
  13. Use the Explorer to work out the size of each structure and where each record of an array begins. Check its arithmetic against the measured figure.
  14. Do the Practice questions in both modes until your streak reaches five.
  15. Answer the Posttest.

Guided practice

Write a function that takes a structure and returns an updated structure — for example one that raises a salary, adds marks, or reduces a stock quantity. Call it from main, assign the result back, and print the record before and after.

Three worked versions are in the Passing a record by value tab: salary, marks and stock quantity. Write your own first.

Practice

  1. Write a function that searches an array of structures for an employee by id and returns that structure. Decide what it should hand back when no employee has that id, and say in your record why you chose it.

In the Searching the records tab, compare the version that returns the record with the version that returns the position, and note in your record which one you would choose if the next step were to give that employee a raise.
