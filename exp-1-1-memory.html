Data Types, Assignment and Expressions

Unit 1 · Decision Making · 22 programs to explore · Estimated time: 60 minutes

Aim

To understand how C stores values of the basic data types in memory, how each assignment changes that memory, and the order in which the operators of an arithmetic expression are applied.

Learning outcomes

After completing this experiment, a student will be able to:

  1. State the size and range of int, float and char, and choose a suitable type for a given quantity.
  2. Predict what happens when a value too large for its type, or a value with a fractional part, is stored.
  3. Trace a sequence of declarations and assignments and state every variable's value at each point.
  4. Apply precedence and associativity to evaluate an expression one operator at a time.
  5. Explain integer division and implicit type promotion, and recognise where an average silently goes wrong.
  6. Swap two variables with and without a temporary variable, and explain why the obvious two-line attempt fails.

Prerequisites

The shape of a simple C program: main(), statements and printf.

How to use this experiment

The Demo is organised into four concepts, each with several programs. Work through a concept completely before moving to the next, and change the input values to test whether your understanding survives different numbers.

Theory

A computer's memory holds nothing but bits. It has no idea whether a particular byte is a number, a letter, or part of a photograph. Everything that gives those bits meaning comes from your program — and almost all of it comes from one word: the type.

What a declaration really does

Writing int marks = 87; settles three things at once. A region of memory is reserved, at some address. Its size is fixed by the type. And the rule for interpreting those bytes is fixed too.

TypeTypical sizeRangeSpecifierGood for
char1 byte−128 to 127%cOne character, or a very small number
int4 bytes−2,147,483,648 to 2,147,483,647%dCounts, marks, indices, years
float4 bytes±3.4 × 1038, about 7 digits%fAverages, measurements, money

These are the sizes of a typical desktop compiler. The C standard fixes only minimums, which is exactly why sizeof exists.

The same bits, two different meanings

The byte pattern 41 in hexadecimal is the number 65 when read as an int, and the letter 'A' when read as a char. Nothing in memory distinguishes them. This is why 'b' - 'a' is a perfectly sensible expression with the value 1 — characters are small integers wearing a costume.

When a value does not fit

A char holds one byte, so it has only 256 possible values. Storing 200 in it does not raise an error and does not store 200. The low eight bits are kept, and read back as a signed byte they give −56. Values wrap around rather than overflow outwards.

The same silent reshaping happens between float and int: int n = 7.9; stores 7. The fraction is not rounded, it is discarded.

Assignment destroys what was there

a = b; does not link a and b. It copies the value in b into a and destroys whatever a held. That destruction is the entire difficulty of swapping two variables.

Precedence and associativity

An expression with several operators is not evaluated left to right. Two fixed rules decide.

LevelOperatorsAssociativity
Highest( )Left to right
*   /   %Left to right
Lowest+   −Left to right

Precedence alone does not settle 100 / 5 * 2, where both operators sit at the same level. Associativity does: left to right, so the division happens first and the answer is 40, not 10.

Integer division and the average that goes wrong

When both operands are integers, / performs integer division and throws the fraction away: 7 / 2 is 3. If either operand is floating-point, the same symbol does real division instead.

So float avg = total / n; with two int variables loses the fraction before the result ever reaches the float. Widening the destination cannot recover what has already been discarded. The fix is to make one operand floating-point: total / (float) n.

Promotion happens per operation

When one operand is an integer and the other floating-point, the integer is converted first and that one operation is done in floating-point. It applies to a single operation, not the whole expression — so an expression can begin in integer arithmetic and switch halfway:

5 / 2 * 2.0   →   2 * 2.0    →   4.0     /* division happened first, in integers */
2.0 * 5 / 2   →   10.0 / 2   →   5.0     /* promotion arrived in time          */

Swapping two variables

The obvious attempt fails. a = b; followed by b = a; leaves both holding the old b, because the first statement has already destroyed a's value.

temp = a;       a = a + b;      /* sum hides both values */
a = b;          b = a - b;      /* sum − b gives old a   */
b = temp;       a = a - b;      /* sum − old a gives b   */

The left version keeps a copy and always works. The right version is a clever trick, but it works only for numbers and the sum can overflow the type even when both original values are perfectly valid. Use a temporary variable in real programs.

Procedure

Step 1

Read the Theory and attempt the Pretest. Note your score before continuing.

Step 2

Open the Demo on the Data types concept. Use the Type Explorer first: enter 200 as a char, then 7.9 as an int, and read what is actually stored.

Step 3

Still on Data types, step through all five programs. At each step look at the memory panel and the byte cells, not only the printed output.

Step 4

Move to Assignment. Before pressing Step, say aloud what the next line will change. Then change the input values at the top and run the same program again.

Step 5

Move to Expressions. Watch which operator is boxed in gold at each step and check it against the precedence table. Compare the two lines of the promotion program carefully.

Step 6

Move to Swapping and run all four programs, including the broken one. Identify the exact statement at which the original value of a is lost.

Step 7

In Practice, do at least six questions in Predict the output and at least three expressions in Pick the next operator.

Step 8

Attempt the Posttest and compare your score with the Pretest.
