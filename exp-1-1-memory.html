Memory, Data Types and Assignment

Unit 1 · Decision Making · Estimated time: 45 minutes

Aim

To understand how C stores values of the basic data types in memory, and how each assignment statement changes the contents of that memory.

Learning outcomes

After completing this experiment, a student will be able to:

  1. State the size in bytes and the range of values of int, float and char, and choose an appropriate type for a given quantity.
  2. Select the correct format specifier for each type in printf.
  3. Trace a sequence of declarations and assignments and state the value of every variable at each point in the program.
  4. Explain why swapping two variables needs a third variable, and how the arithmetic method avoids it.
  5. Predict what happens when a value outside the range of a type is stored in it.

Prerequisites

The structure of a simple C program: main(), statements, and printf.

Theory

Every variable in a C program is a named region of memory. Three things are fixed the moment the variable is declared: its name, the address where it lives, and its type. The type decides how many bytes are reserved and how the bits in those bytes are to be interpreted.

The basic types

TypeTypical sizeRangeSpecifierUsed for
char1 byte-128 to 127%cA single character or a very small number
int4 bytes-2,147,483,648 to 2,147,483,647%dWhole numbers: counts, marks, indices
float4 bytesabout ±3.4 × 1038, ~7 digits of precision%fReal numbers: averages, measurements

Sizes are those of a typical 32-bit or 64-bit desktop compiler. The C standard fixes only the minimum sizes, which is why sizeof exists: it reports what the compiler in front of you actually chose.

The same bits mean different things

Memory holds only bits. The type is what gives them meaning. The byte pattern 41 in hexadecimal is the number 65 when read as an int, and the letter 'A' when read as a char. Nothing in the memory itself distinguishes them; the type in the declaration does. This is why a wrong format specifier in printf prints nonsense rather than raising an error — the program obediently reads the bits the way you asked.

What happens when a value does not fit

A char holds one byte, so it can represent only 256 distinct values. Storing 200 in a signed char does not produce an error and does not store 200. The low eight bits are kept, and those bits read as a signed value give -56. Values wrap around rather than overflowing outwards. The same happens to an int, only at a much larger boundary.

Assignment changes one box at a time

The statement a = b; does not connect a and b. It copies the value currently in b into a, and destroys whatever a held before. That destruction is the whole difficulty of swapping.

Swapping two variables

To exchange the values of a and b, writing a = b; followed by b = a; fails: by the time the second statement runs, the original value of a is already gone, and both variables end up holding the old b.

The reliable method keeps a copy:

temp = a;   /* save a          */
a = b;      /* a now holds b   */
b = temp;   /* b gets old a    */

The arithmetic method avoids the third variable by hiding both values inside one:

a = a + b;  /* a holds the sum of both  */
b = a - b;  /* sum minus b gives old a  */
a = a - b;  /* sum minus old a gives b  */

It is a neat trick, but it is worse code: it works only for numbers, and the sum can overflow the range of the type even when both original values are perfectly valid. Use the temporary variable in real programs.

Procedure

Step 1

Read the Theory and attempt the Pretest. Note your score before continuing.

Step 2

Open the Demo. Select Declarations and sizes and press Step repeatedly. After each step, look at the memory panel: watch a new box appear, note its address and how many byte cells it occupies, and read the observation.
