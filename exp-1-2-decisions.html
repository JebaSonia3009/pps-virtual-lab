Decision Making with if…else

Unit 1 · Decision Making · 23 programs to explore · Estimated time: 60 minutes

Aim

To understand how a C program chooses between different courses of action using if, if…else and the else-if ladder, and how a condition is worked out to decide which path the program takes.

Learning outcomes

After completing this experiment, a student will be able to:

  1. Write conditions using the relational operators and say whether a condition is true or false for given values.
  2. Explain that in C a condition produces the number 1 for true and 0 for false.
  3. Combine conditions with &&, || and !.
  4. Trace an else-if ladder and say exactly which conditions were tested and which were skipped.
  5. Write a range check to validate an input value.
  6. Solve the standard classification problems: odd or even, positive or negative, vowel or consonant, leap year, character type, and eligibility checks.

Prerequisites

Experiment 1.1 — data types, assignment and expressions.

How to use this experiment

The Demo has four concepts, each with several programs. Finish one concept before moving to the next, and change the input values to check that your understanding still holds for different numbers.

Theory

Every program you have written so far runs straight from the first statement to the last. A decision statement changes that. It asks a question, and depending on the answer it runs one block of statements instead of another. The statements that are not chosen are not executed at all — the program simply jumps over them.

The shape of an if statement

if (condition) {
    /* runs only when the condition is true */
}

If the condition is false, the whole block is skipped and the program carries on from the line after the closing brace. Nothing is printed, nothing is changed.

Choosing between two paths

if (condition) {
    /* runs when true  */
} else {
    /* runs when false */
}

Exactly one of the two blocks runs — never both, and never neither.

What a condition actually is

C has no separate true/false type. A condition is an ordinary number. A comparison such as 7 > 3 produces the value 1 when it holds and 0 when it does not. You can store that result in an int and print it.

Going the other way, when a number is used as a condition C asks only one question: is it zero? Zero means false, and every other value — positive or negative — means true. That is why if (n) is a valid way of writing if (n != 0).

The relational operators

OperatorMeaningExampleResult
==is equal to5 == 51 (true)
!=is not equal to5 != 31 (true)
>is greater than3 > 50 (false)
<is less than3 < 51 (true)
>=is greater than or equal to5 >= 51 (true)
<=is less than or equal to6 <= 50 (false)

Take care: == asks a question, while a single = stores a value. a == b tests whether they are equal; a = b copies b into a. They look similar and mean completely different things.

Combining conditions

OperatorNameTrue when
&&ANDboth sides are true
||ORat least one side is true
!NOTthe thing after it is false

Arithmetic is worked out first, then the comparisons, then &&, and last of all ||. So a + 1 > b && c == d means ((a + 1) > b) && (c == d). Adding brackets of your own makes the condition easier for a reader, and they cost nothing.

C stops as soon as it knows the answer

For A && B, if A is false then the whole thing must be false, so B is never worked out. For A || B, if A is true the answer is already known and B is skipped.

This is a promise the language makes, not an accident, and it is useful. In if (n != 0 && total / n > 5) the division never happens when n is zero, so the program cannot crash.

The else-if ladder

if (marks >= 90) {
    printf("Grade A");
} else if (marks >= 75) {
    printf("Grade B");
} else if (marks >= 60) {
    printf("Grade C");
} else {
    printf("Fail");
}

The conditions are tested from the top, one at a time, and C stops at the first one that is true. Every condition below it is skipped without even being looked at. Only one block ever runs.

This is why the order of the tests matters so much. If you wrote marks >= 40 first, then a student with 82 marks would match it immediately and be given Grade D — the test for Grade B below would never be reached. Always start a ladder of bands with the narrowest condition.

Range checks

To test whether a value lies between two limits, both ends must be written out and joined with &&:

if (marks >= 0 && marks <= 100) {   /* correct   */

if (0 <= marks <= 100) {             /* WRONG     */

The second line compiles but does not do what it looks like. It is a very common beginner's mistake, so write range checks with && every time.

Checking a value before using it is called validating the input, and it belongs at the top of the ladder so that nonsense values are caught before any other test runs.

Characters can be compared too

A char holds a small number — the code of the character — so characters can be compared with the same operators. Because the letters a to z sit next to each other in order, ch >= 'a' && ch <= 'z' tests whether ch is a small letter. The same idea works for 'A' to 'Z' and for the digits '0' to '9'.
